# owen-qa-skill

[English](README.md)

앱을 운영과 같은 조건에서 테스트하는 Claude Code QA 스킬입니다. 인스턴스를 여러 개 띄우고, 실제 의존 서비스를 쓰고, 작업이 진행되는 중에 재시작, 강제 종료, 장애를 일으킵니다.

보통 QA는 인스턴스 하나에서 정상 흐름만 확인합니다. 운영까지 가는 버그는 대개 다른 곳에 있습니다.

- 멱등 키를 프로세스 메모리에 둬서 인스턴스 두 개가 같은 결제를 두 번 처리합니다.
- 워커가 큐에서 작업을 먼저 꺼낸 뒤 재시작돼서 작업이 사라집니다.
- DB가 30초 끊긴 뒤 워커가 다시 연결하지 못합니다.
- 모든 요청이 실패하는데 헬스 체크는 "ok"를 돌려줍니다.

`/qa`는 이런 문제를 일부러 찾고, 찾은 문제마다 그것을 보여 주는 명령과 출력을 함께 남깁니다.

## 하는 일

1. **범위 파악.** 대상을 빌드하고 실행하는 방법을 읽습니다. 화면, API, 워커 같은 표면과 상태 저장소, 모든 시간 제한(타임아웃, TTL, 자격 증명 수명, 종료 유예 시간)을 정리합니다. 어떤 장애 뒤에도 지켜져야 할 조건(불변 조건)을 적고 짧은 테스트 계획을 세웁니다.
2. **운영처럼 실행.** 상태 없는 서비스는 2개 이상 띄우고 DB, 큐, 캐시는 실제 서비스를 씁니다.
3. **기준선 확인.** 프로젝트의 빌드, 테스트, 린터를 돌립니다.
4. **기능 점검.** API, 웹 UI, CLI, 워커, 예약 작업, 웹훅, 마이그레이션, 인프라 코드를 점검합니다.
5. **장애 내성 점검.**
   - 기본: 부하 중 순차 재시작, 작업 중 SIGTERM과 SIGKILL, 의존 서비스 장애, 여러 인스턴스에 같은 요청 동시 전송, 시간 제한 불일치
   - `deep`: 중복 메시지 전달, 이전 버전과 새 버전 동시 실행, 스케일 변경, 지연 주입도 추가
6. **배포 설정 검토.** 위 점검에서 실제로 관찰한 동작과 맞춰 봅니다.
7. **보고서.** 판정, 심각도순 발견 사항과 재현 명령, 점검 범위 표, 정리한 내용을 담습니다.
8. **수정 모드.** 요청할 때만 동작합니다. 실패하는 테스트를 먼저 쓰고, 고친 다음, 같은 점검을 다시 돌립니다.

## 설치

플러그인으로:

```
/plugin marketplace add yun4010608-netizen/owen-qa-skill
/plugin install owen-qa-skill@owen-qa-skill
```

또는 `skills/qa`를 `~/.claude/skills/qa`(모든 프로젝트)나 `.claude/skills/qa`(한 프로젝트)에 복사합니다.

## 사용법

```
/qa quick                # 약 10분: 큰 위험만 빠르게, 짧은 답
/qa                      # standard, 약 30분: 전체 보고서
/qa deep                 # 약 60분: 모든 시나리오, 증거 부록, 남은 위험
/qa deep 2h              # 시간 예산 직접 지정 ("시간 제한 없이"도 가능)
/qa fix                  # 보고 후, 문제마다 회귀 테스트를 쓰고 수정
/qa http://localhost:8080
```

| 깊이 | 시간 | 하는 일 | 보고서 |
|---|---|---|---|
| `quick` | 약 10분 | 주요 흐름, 다중 인스턴스 위험 코드 훑기, 위험도순 장애 점검 최대 3개 | 판정, 주요 발견, 확인하지 않은 것 |
| `standard` | 약 30분 | 바뀌었거나 중요한 표면 전체, 핵심 장애 시나리오, 설정 검토 | 불변 조건과 점검 범위가 있는 전체 보고서 |
| `deep` | 약 60분 | 모든 표면과 의존 서비스, 장애 시나리오 전체, 장시간 부하, 실패한 점검 반복 | 전체 보고서와 증거 부록, 남은 위험, 수정 계획 |

깊이마다 가장 중요한 점검부터 하고, 시간이 모자라 못 한 것은 목록으로 남깁니다. "배포 전에 빠르게 봐줘"라고 하면 `quick`, "최대한 자세하게 봐줘"라고 하면 `deep`으로 돕니다.

플러그인으로 설치하면 명령은 `/owen-qa-skill:qa`입니다. "이거 배포해도 돼?", "워커 재시작하면 작업 날아가?" 같은 질문에도 Claude가 이 스킬을 씁니다.

## 안전장치

- 모든 것을 별도 Compose 프로젝트나 네임스페이스에서 띄우므로, 사용자가 띄워 둔 환경을 스케일하거나 재시작하거나 내리지 않습니다.
- 프로세스 종료, 의존 서비스 중지, 장애 주입처럼 되돌리기 어려운 단계는 스킬이 직접 만든 환경이나 사용자가 버려도 된다고 한 환경에서만 실행합니다.
- 공유 환경에서는 그런 단계마다 먼저 묻습니다.
- 운영 환경은 사용자가 단계별로 승인하지 않는 한 읽기만 합니다.
- 정리할 때는 이번 실행이 만든 것만 지웁니다. 시작 전에 있던 컨테이너, 이미지, 볼륨을 기록해 두고, prune 명령은 쓰지 않습니다.
- 비밀값은 보고서와 로그에 남기지 않습니다.
- 텔레메트리가 없습니다. 스킬이 스스로 외부로 요청을 보내지 않습니다. 함께 들어 있는 스크립트는 `scripts/load.py`(파이썬 표준 라이브러리만 쓰고 지정한 대상에만 요청)와 `scripts/snapshot.sh`(실행 전후의 로컬 Docker·Kubernetes 자원 목록)입니다.

## 필요한 것

- Claude Code
- `load.py`용 Python 3.8 이상
- 대상을 실행할 도구: Docker와 Compose, `kubectl`, 또는 일반 프로세스
- 선택: 웹 UI 테스트용 브라우저 MCP 서버(Playwright, Chrome DevTools)

## 평가

`evals/fixtures/orders-service`는 알려진 버그 9개를 넣어 둔 작은 주문 서비스입니다. 일부러 망가뜨리고 보안 설정도 빼 둔 코드라 보안 스캐너가 경고를 냅니다. 배포하지 마세요. `evals/evals.json`에 테스트 프롬프트와 정답이 있습니다. 스킬을 고친 뒤에도 찾아야 할 문제를 여전히 찾는지 확인할 때 씁니다.

`evals/trigger/`는 Claude가 언제 이 스킬을 부르는지 확인합니다. 불러야 하는 요청 10개와 비슷하지만 부르면 안 되는 요청 10개를, 설치된 스킬에 읽기 전용 도구만 허용해서 돌립니다(`python3 evals/trigger/trigger_check.py evals/trigger/queries.json <샘플 저장소> out.json 3`). 지금 description은 매번 20/20입니다.
